## 今回修正した点

| 指摘                                                                          | 対応                                                                                                  |
| ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 配置抽出後に元metadataが変わると、解析metadataと配置が別世代になる            | 一度取得したbytesをSHA-256付き専用キーへ保存し、配置と解析に同じ内容を使用。typedの既存checksumも照合 |
| 不正・別形式のmetadataが併存すると、一意にbind可能なJSON v1まで利用不可になる | 有効なJSON v1候補の選択を現行入力契約に合わせる                                                       |
| 1件のmetadata欠損が利用可否一覧全体を失敗させる                               | その入力を利用不可にし、他の計測の判定は返す                                                          |
| 固定先へのPUT失敗が通常PDRまで止める                                          | BLE用配置のみ利用不可。非BLEは元キーと取得時checksumで継続し、実行時に変更を検出                      |
| 保存障害・読み込み障害・checksum不一致を区別できない                          | recording IDとread/checksum/store段階をサーバーログへ記録                                             |

providerからbindingまでの結合テストでは、固定先への保存直後に元metadataを変更しても、
配置とbind先metadataが同じ取得内容に基づくことを検証する。
実ストレージの障害を起こした試験は行わず、障害時はモックとコード経路で検証する。

## 地図画像などを今回まとめて履歴化しない判断

今回の保証は「計測時ビーコン配置と、それを抽出したmetadataを解析に使う」ことに限定する。
軌跡全体の完全再現を保証するものではない。

現行のフロア更新APIは画像差し替えを受け付けず、新規フロアの地図は別UUIDのキーへ保存する。
run作成時の地図hashはmanifestへ保存され、Nozomiは実行時に個別ファイルのchecksumを検証する。
通常操作での地図画像差し替えへの全面対応を、このビーコン不具合修正の前提とはしない。

ただし縮尺は現在のAPIでも変更できる。同じpixel座標でも縮尺が変わればメートル距離が変わる。
現在値を使う再解析は計測当時と同じ条件とは限らず、この既存リスクは残る。
過去metadataに保存されていない地図や縮尺を、現在値から「当時の値」として補完してはいけない。

## 次の優先対応

| 優先度 | 対応                                                                                       | 現在残る問題                                                                                   |
| ------ | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| 最優先 | 地図bytes/hash・画像寸法・m/px・座標系を一つのfloor revisionとして保存し、計測へ関連付ける | 現在の縮尺変更が過去計測の距離解釈へ影響する。画像hashだけでは解決しない                       |
| 次     | 過去runのmanifest・実効パラメーターを使う再現実行と、現在設定を使う再解析を分ける          | 現在のretryは入力・地図・縮尺・開始条件を再解決する                                            |
| 次     | 省略された実効既定値、身長、確定seed、Nozomi/Rikka commitまたはimage digestをrunに記録する | 同じpipeline定義digestでもエンジンや既定値の変更で結果が変わる。seed未指定のPFは完全一致しない |
| 継続   | 入力・成果物の保持期間、世代保管、削除・上書き方針を定める                                 | 内容hashと検証は改変検出であり、長期保管そのものの保証ではない                                 |

地図差し替え機能を追加する際はfloor revisionを先に整える。
再現実行の保証水準は、入力・条件の一致、軌跡の許容誤差内一致、動画までの完全一致を区別して決める。
